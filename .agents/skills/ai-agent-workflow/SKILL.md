## 一、5级使用框架

### 第1级：基础代码生成
**适用场景：** 快速原型、小功能开发
**复杂度：** 低
**通用能力：**
- 简单函数编写
- 单文件代码补全
- 基础代码片段生成
- 代码解释和翻译

**使用方法：**
1. 给出明确的函数签名和功能描述
2. 指定输入输出格式
3. 说明边界条件

**通用提示词模板：**
```
请用[编程语言]编写一个[功能描述]的函数/类。

要求：
- 输入：[输入参数和类型]
- 输出：[返回值和类型]
- 边界条件：[特殊情况处理]
- 代码风格：[遵循的规范]
```

---

## 二、核心工作流程

### 步骤1：明确任务描述

**原则：**
- 给AI清晰、具体的指令
- 说明输入和输出
- 指定编程语言和框架
- 描述边界条件和约束

**检查清单：**
- [ ] 任务目标明确
- [ ] 输入输出格式清晰
- [ ] 技术栈已指定
- [ ] 约束条件已说明

---

### 步骤2：提供上下文

**原则：**
- 分享相关代码、文档或需求
- 提供现有代码片段
- 分享技术规范
- 说明业务逻辑

**上下文类型：**
1. **代码上下文**：现有代码、项目结构
2. **业务上下文**：需求文档、业务规则
3. **技术上下文**：框架版本、依赖关系
4. **环境上下文**：运行环境、部署要求

**不同工具的上下文提供方式：**

| 工具 | 上下文方式 |
|------|------------|
| Codex | `#file` 引用文件，粘贴代码 |
| Copilot | 注释描述，代码上下文 |
| Claude | 上传文件，粘贴代码 |
| GPT-4 | 粘贴代码，上传文件 |
| Cursor | `@` 引用文件，选中代码 |

---

### 步骤3：分阶段执行

**原则：**
- 复杂任务拆分成小步骤
- 先实现核心逻辑
- 再添加错误处理
- 最后优化和完善

**执行顺序：**
```
1. 核心功能实现
   ↓
2. 错误处理完善
   ↓
3. 边界条件处理
   ↓
4. 性能优化
   ↓
5. 代码美化
```

---

### 步骤4：验证结果

**原则：**
- 检查生成的代码是否符合预期
- 代码审查
- 功能测试
- 性能验证

**验证方法：**
1. **静态检查**：代码规范、命名规范
2. **功能测试**：单元测试、集成测试
3. **性能测试**：响应时间、资源占用
4. **安全检查**：漏洞扫描、权限验证

---

### 步骤5：迭代优化

**原则：**
- 根据反馈调整提示词
- 优化指令表达
- 补充缺失信息
- 完善功能细节

**优化方向：**
- 提示词更精确
- 上下文更完整
- 约束条件更明确
- 验收标准更具体

## 四、通用最佳实践

### 4.1 提示词优化

**原则：**
1. **具体明确**：避免模糊描述
2. **完整上下文**：提供必要信息
3. **分步执行**：复杂任务拆分
4. **验证反馈**：及时检查结果

**好的提示词：**
