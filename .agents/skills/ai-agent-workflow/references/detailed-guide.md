## 第1级：基础代码生成

### 核心概念
基础代码生成是AI智能体最基本的功能，适用于快速原型开发和小功能实现。

### 使用场景
- 快速生成函数实现
- 代码片段补全
- 简单算法实现
- 数据格式转换
- 代码解释和翻译

### 最佳实践

#### 1. 明确函数签名
```python
# 好的示例
def calculate_average(numbers: list[float]) -> float:
    """计算数字列表的平均值"""
    pass

# 不好的示例
def avg(nums):
    pass
```

#### 2. 提供完整上下文
```python
# 好的示例
"""
输入：一个包含学生成绩的字典列表
输出：每个学生的平均成绩

示例输入：
[{"name": "Alice", "scores": [85, 90, 88]}, {"name": "Bob", "scores": [78, 82, 80]}]

示例输出：
[{"name": "Alice", "average": 87.67}, {"name": "Bob", "average": 79.33}]
"""
def calculate_student_averages(students: list[dict]) -> list[dict]:
    pass
```

#### 3. 指定技术要求
```python
# 好的示例
"""
要求：
- 使用列表推导式
- 保留2位小数
- 处理空列表情况
- 添加类型注解
"""
def process_scores(scores: list[int]) -> list[float]:
    pass
```

### 常见错误

1. **描述过于模糊**
   ```
   ❌ "写一个函数"
   ✅ "用Python编写一个计算斐波那契数列的函数，输入n返回前n项"
   ```

2. **缺少边界条件**
   ```
   ❌ "计算列表平均值"
   ✅ "计算列表平均值，空列表返回0.0"
   ```

3. **没有指定技术栈**
   ```
   ❌ "写一个HTTP请求"
   ✅ "用Python的requests库发送GET请求"
   ```

## 第2级：代码理解与修改

### 核心概念
理解现有代码并进行修改，适用于项目维护和技术债务清理。

### 使用场景
- 代码重构优化
- Bug修复调试
- 性能优化
- 代码规范调整
- 代码审查

### 最佳实践

#### 1. 提供完整代码上下文
```python
# 现有代码
def process_data(data):
    result = []
    for item in data:
        if item['type'] == 'A':
            result.append(item['value'] * 2)
        elif item['type'] == 'B':
            result.append(item['value'] * 3)
        else:
            result.append(item['value'])
    return result

# 修改需求
"""
重构上述代码，要求：
1. 使用策略模式
2. 添加类型注解
3. 提高可扩展性
4. 保持功能不变
"""
```

#### 2. 明确修改目标
```python
# 问题代码
def fetch_user(user_id):
    try:
        user = db.query(f"SELECT * FROM users WHERE id = {user_id}")
        return user
    except Exception as e:
        print(f"Error: {e}")
        return None

# 修改目标
"""
修复以下问题：
1. SQL注入漏洞
2. 异常处理不完善
3. 缺少日志记录
4. 没有类型注解
"""
```

#### 3. 说明约束条件
```python
# 约束条件
"""
重构时需要：
- 保持向后兼容
- 不改变公共API
- 遵循项目代码规范
- 保持性能不变
"""
```

### 常见错误

1. **缺少修改原因**
   ```
   ❌ "重构这个函数"
   ✅ "这个函数有SQL注入漏洞，请重构并修复"
   ```

2. **没有说明约束**
   ```
   ❌ "优化这段代码"
   ✅ "优化这段代码，但保持向后兼容，不改变公共API"
   ```

3. **忽略测试**
   ```
   ❌ "只修改代码"
   ✅ "修改代码并更新对应的测试用例"
   ```

## 第3级：多文件项目工作

### 核心概念
跨文件的功能实现，适用于中等规模的功能开发。

### 使用场景
- 功能模块开发
- API接口实现
- 数据库交互
- 前后端联调
- 微服务开发

### 最佳实践

#### 1. 描述项目架构
```
项目结构：
project/
├── src/
│   ├── models/          # 数据模型
│   ├── services/        # 业务逻辑
│   ├── controllers/     # API接口
│   └── utils/          # 工具函数
├── tests/               # 测试文件
└── docs/               # 文档
```

#### 2. 明确模块职责
```
模块职责：
- models/user.py: 用户数据模型
- services/auth.py: 认证服务（登录、注册、权限）
- controllers/api.py: REST API接口
- utils/helpers.py: 通用工具函数
```

#### 3. 定义模块接口
```python
# services/auth.py 接口定义
class AuthService:
    def register(self, username: str, password: str) -> User:
        """用户注册"""
        pass
    
    def login(self, username: str, password: str) -> str:
        """用户登录，返回JWT token"""
        pass
    
    def verify_token(self, token: str) -> bool:
        """验证token有效性"""
        pass
```

### 任务分解示例

#### 完整功能实现
```
任务：实现用户认证系统

子任务：
1. 设计数据库表结构
   - users表
   - roles表
   - user_roles表

2. 实现数据模型
   - User模型
   - Role模型
   - 关联关系

3. 实现认证服务
   - 注册功能
   - 登录功能
   - Token管理

4. 实现API接口
   - POST /api/auth/register
   - POST /api/auth/login
   - GET /api/auth/me

5. 编写测试用例
   - 单元测试
   - 集成测试
   - API测试
```

### 常见错误

1. **架构不清晰**
   ```
   ❌ "实现用户功能"
   ✅ "按照MVC模式实现用户管理模块，包括数据模型、服务层和API接口"
   ```

2. **接口不明确**
   ```
   ❌ "实现登录功能"
   ✅ "实现登录功能，接口：POST /api/login，输入：username/password，输出：JWT token"
   ```

3. **依赖关系混乱**
   ```
   ❌ "同时实现所有模块"
   ✅ "按依赖顺序实现：数据模型 → 服务层 → API接口 → 测试"
   ```

## 第4级：复杂架构设计

### 核心概念
系统架构设计和优化，适用于大型系统重构和架构升级。

### 使用场景
- 系统性能优化
- 微服务架构设计
- 高可用系统设计
- 安全架构设计
- 技术选型

### 最佳实践

#### 1. 描述现有系统问题
```
现有系统问题：
1. 性能问题
   - 数据库查询慢（平均500ms）
   - 接口响应时间长
   - 并发处理能力差

2. 架构问题
   - 单体应用，难以扩展
   - 模块耦合度高
   - 缺少缓存机制

3. 运维问题
   - 部署复杂
   - 监控不足
   - 扩展困难
```

#### 2. 明确优化目标
```
优化目标：
1. 性能目标
   - 响应时间 < 100ms
   - 支持1000 QPS
   - 99.9%可用性

2. 架构目标
   - 微服务架构
   - 模块解耦
   - 水平扩展

3. 运维目标
   - 容器化部署
   - 自动化运维
   - 完善监控
```

#### 3. 提供约束条件
```
约束条件：
1. 技术约束
   - 保持现有数据库
   - 兼容现有API
   - 渐进式重构

2. 资源约束
   - 团队规模：5人
   - 时间：3个月
   - 预算：有限

3. 业务约束
   - 不能停止服务
   - 数据不能丢失
   - 功能不能退化
```

### 常见错误

1. **问题描述不完整**
   ```
   ❌ "系统很慢"
   ✅ "数据库查询平均500ms，接口响应时间>1s，并发支持<100"
   ```

2. **目标不具体**
   ```
   ❌ "提高性能"
   ✅ "响应时间<100ms，支持1000QPS，99.9%可用性"
   ```

3. **缺少约束**
   ```
   ❌ "设计新架构"
   ✅ "在保持现有数据库的前提下，设计微服务架构"
   ```

## 工具适配指南

### 通用原则

无论使用哪种AI工具，以下原则都适用：

1. **清晰的任务描述**
   - 具体明确
   - 完整上下文
   - 明确约束

2. **分阶段执行**
   - 复杂任务拆分
   - 逐步验证
   - 持续优化

3. **质量控制**
   - 代码审查
   - 测试验证
   - 安全检查

### 工具特性对比

| 特性 | Codex | Copilot | Claude | GPT-4 | Cursor |
|------|-------|---------|--------|-------|--------|
| 执行方式 | 云端 | 本地 | 云端 | 云端 | 本地 |
| 上下文 | 文件引用 | 代码上下文 | 文件上传 | 文本粘贴 | 文件引用 |
| 自主性 | 高 | 低 | 中 | 中 | 中 |
| 适合场景 | 复杂任务 | 日常编码 | 深度分析 | 通用任务 | IDE集成 |
| 响应速度 | 中 | 快 | 中 | 中 | 快 |
| 代码理解 | 强 | 中 | 强 | 中 | 强 |

### 选择建议

**根据任务复杂度选择：**
- **简单任务**：Copilot、Cursor（快速补全）
- **中等任务**：GPT-4、Claude（通用能力强）
- **复杂任务**：Codex（自主性强）
- **深度分析**：Claude（长上下文）
- **日常编码**：Copilot、Cursor（IDE集成）

**根据使用场景选择：**
- **快速原型**：Copilot、Cursor
- **代码审查**：Claude、GPT-4
- **架构设计**：Claude、GPT-4
- **复杂实现**：Codex
- **团队协作**：GPT-4、Claude
